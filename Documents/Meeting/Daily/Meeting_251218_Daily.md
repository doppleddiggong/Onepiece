# 2025-12-18 데일리 회의

## 1. 개요
- 일자: 2025년 12월 18일
- 참석: 클라이언트, AI, 백엔드
- 목적: **시연 기준 SpeakQuest 완성도 점검 및 데모 전략 정리**

---

## 2. 논의 요약

### 2.1 주요 논의
- SpeakQuest **Step 1~4 전체 플로우 구현 완료** 상태 확인.
- 결과창(Result UI)까지 정상 노출되며, 현재 단계는 **디테일 및 UX 보완** 중심.
- 교수진 요청 사항:
  - “이제부터는 매일 시연 가능 상태로 유지”
  - 발표/데모 전제 개발로 전환 필요.

### 2.2 기술 / UX 관련 논의
- **플레이 가이드 부족 문제**
  - “어디로 가야 하는지”, “무엇을 해야 하는지” 인지가 어려움.
  - 해결 방향:
    - 화면 상단 **방향 내비게이션(UI Compass)** 추가
    - 퀘스트 상태 정보 명확화
- **Result UI**
  - 숫자 점수 다수 제거 → 정성 평가 중심으로 정리
  - 텍스트 길이:
    - 50~100자 내외가 적절
    - Writing 결과는 **단어 단위 응답** 유도 방향 합의
- **Writing Quest**
  - 현재 5문항 → **3문항으로 축소 검토**
  - 존댓말/문장 단위 응답은 학습 난이도 과도 → 프롬프트 제어 필요
- **서버 데이터 이슈**
  - Result Rate 값이 0으로 고정 수신됨
  - 실제 데이터는 정상 → **클라이언트 파싱 또는 매핑 문제 가능성**
- **멀티플레이**
  - 평가 요구사항으로 2인 플레이 필요
  - 단, 최종 발표/시연 시에는 **1인 플레이 전환 가능** 의견 일치

### 2.3 시연 / 발표 전략
- 전체 시연 시:
  - Step 1~2는 빠르게 스킵
  - **Step 3~4 중심 시연**이 집중도 높음
- 시연 전:
  - 하위층에서 1회 사전 플레이 후 상층 시연 권장
- 발표 자료:
  - 기능 나열이 아닌
    - “인터뷰 생성”
    - “읽기/듣기/쓰기/말하기 평가”
    - “AI 피드백 흐름”
    단위로 구조화 예정
- 토요일:
  - 플레이 영상 대량 캡처 계획

## 4. 회고

### 4.1 잘된 점 (Keep)
- SpeakQuest 핵심 플로우는 **알파 기준 완성 단계** 진입.
- 실제 시연을 전제로 한 UX 문제들이 명확히 드러남.
- 팀 내 역할 분담이 자연스럽게 이루어짐.

### 4.2 미진한 점 (Problem)
- 플레이 가이드 부재로 첫 플레이 진입 장벽 존재.
- Writing 학습 난이도 조절이 늦어진 점.

### 4.3 다음 단계 (Try)
- “기능 추가”보다 **시연 안정성 + 설명력** 최우선.
- 발표 기준 시나리오를 고정하고, 나머지는 스킵 전략 활용.
- 이후 포트폴리오 활용을 고려한 구조 정리 병행.
