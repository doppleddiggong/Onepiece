## 2. 논의 요약

### 2.1. 주요 논의
- **인터뷰 API 구조 정리 및 연동 준비**
  - `hello` / `post single` / `post batch` API 사용 범위 명확화  
  - 클라이언트는 토큰 자동 헤더 삽입 방식으로 개발  
  - Swagger에서 토큰 삽입은 제한적 → Postman 사용 권장

- **쓰기·듣기·말하기 테스트 기본 구조 확정**
  - 쓰기: 글자 수 제한보다 **스크롤 UI 기반 입력**  
  - 듣기: 서버 음성 데이터를 **바이너리 → Wave 파일 변환 → 재생**  
  - 말하기: 초기 버전은 **단문 평가 기반**  
    - 평가 기준은 50~70점 사이  
    - STT → 텍스트 평가 우선 적용  
    - TTS 피드백은 알파 이후 확장

- **시나리오 구조 통일 필요**
  - 기존 1,2,3,4 숫자 기반 → `READ / WRITE / LISTEN / SPEAK` Enum으로 전환  
  - GameState/GameMode에 시나리오 시스템 구성  
  - NPC 심사관도 시나리오 시스템 사용

- **서버 사이드 Redis 캐싱**
  - 생성된 인터뷰/문제 데이터를 유저별로 Redis에 저장  
  - 평가 요청 시 시나리오 ID 기반으로 정답 매칭 처리

- **Postman 교육 필요**
  - 팀 내 API 테스트 경험 부족  
  - Postman으로 토큰/헤더/폼데이터 테스트 방법 공유 예정

- **프로토타입 발표 방향 조정**
  - 문서 중심 발표 → **시연 위주**로 변경  
  - Step1~4 전체 학습 흐름이 돌아가는 형태가 핵심  
  - 슬라이드는 **구성도 1장 + 시나리오 차트 1장** 정도로 최소화
