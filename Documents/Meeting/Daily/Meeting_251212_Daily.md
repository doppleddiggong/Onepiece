# 2025-12-12 데일리 회의

## 1. 개요
- **일자:** 2025-12-12
- **참석:** 배주백 외 팀원
- **키워드:** SpeakQuest, WriteQuest, ListenQuest, API 안정화, 튜터 에이전트, 서버 고도화

---

## 2. 논의 요약

### 2.1. 주요 논의
- 프로젝트가 **중반 이후 단계**에 진입했으며, 단순 기능 추가보다 **안정화 + 고도화 중심**으로 전환 필요성 공유.
- AI 활용 여부가 개인 역량 및 채용 트렌드에서 점점 더 중요해지고 있으며, 기존 숙련 기술만 반복하는 구조에 대한 문제의식 논의.
- 각 파트는 “지금 당장 돌아가는 것”을 기준으로 **주말 내 정리 → 다음 주 시연 대응** 흐름으로 합의.

### 2.2. 기술 / 기획 관련 논의
- **클라이언트**
  - UI 전반 구조 정리 완료.
  - SpeakQuest 기준으로 UI 및 플로우 재구현 진행 중.
  - WriteQuest는 UI 대부분 마무리되었으며 API 연동 단계 진입.
  - ListenQuest는 맵 구성이 미흡하여 맵 재구성 작업 진행 중.
- **AI / 서버**
  - 백엔드 기본 기능은 대부분 완료 단계.
  - Redis 기반 비동기 처리로 Speak / Write 데이터 생성 파이프라인 구성됨.
  - STT / LLM 응답 속도는 양호하나, **TTS 오디오 생성 구간에서 대기 시간 발생**.
  - 오디오 생성은 비동기 처리 또는 스킵 가능성 검토.
  - 다음 주부터 **튜터 에이전트 작업** 착수 예정, 그 전까지는 안정화와 고도화에 집중.

### 2.3. 일정 / 운영 관련 논의
- 주말 동안 SpeakQuest 핵심 로직을 우선 마무리하여 **월요일 강사 시연 대응** 준비.
- 맵, 웹, 서버 작업 시 **작업 시작/종료를 반드시 공유**하는 운영 규칙 재확인.
  - 공유 없이 진행된 작업은 충돌 시 폐기 원칙.
- 서버 장애 발생 시 즉시 태깅하여 공유하고, 원인 확인 후 대응.

## 4. 회고

### 4.1. 잘된 점 (Keep)
- 각 파트별 구현 현황과 병목 지점이 명확히 공유됨.
- “지금 필요한 것”과 “다음 단계”가 분리되어 논의됨.

### 4.2. 미진한 점 (Problem)
- Speak / Write 생성 파이프라인에서 대기 시간이 사용자 경험에 영향을 줄 가능성 존재.
- 맵 작업 및 병행 개발 시 충돌 위험 여전함.

### 4.3. 다음 단계 (Try)
- 주말 동안 핵심 시나리오를 실제 플레이 기준으로 점검.
- 다음 주부터 튜터 에이전트 작업을 기존 시스템 부담을 최소화하는 방향으로 단계적 연결.
