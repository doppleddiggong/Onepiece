## 2. 논의 요약

### 2.1. 서비스·광고·질문지 설계
- **입국 전 사용자 질문지 시스템 도입**
  - 로그인 후 로비 진입 전에 질문지(텍스트 타이핑)를 서버로 제출
  - *국적/이름 등 기본 정보 + 관심사 1~2개* 수집  
  - 관심사는 광고 추천, 개인화 학습, 향후 시나리오 분기 등에 활용됨
- **광고 구조 논의**
  - 유저 관심사 기반 이미지·영상 광고 제공 가능
  - 광고는 질문지 정보 또는 LLM 기반 실시간 추천으로 제공 가능
  - *“돈벌이 구조(BM) 세팅”* 관점에서 필수 요소로 간주됨
- **질문지 생성 정책**
  - 접속 시마다 생성할지, 일정 주기로 갱신할지 선택 필요  
  - 서버는 “없으면 생성 → 채워지면 다음 질문 생성” 방식으로 관리 제안
  - 쿠키·디바이스 기반 추적은 불가 → 서버 세션/DB 관리 중심

### 2.2. 아이템·상점·보상 구조
- **아이템 해금 구조**
  - 서버는 “해금정보(Unlock)”와 “장착정보(Equip)” 두 개로 관리
  - 슬롯 구성: 머리/몸/다리(3개 고정)
  - 아이템 ID는 서버 인덱스 기반, 클라이언트는 데이터시트로 표현
- **획득 방식**
  - 기본은 업적형(퀘스트 달성) 또는 **골드 구매 방식**
  - 프로토 단계에서는 상점 기능 제외, 이후 버전에서 상점/구매 API 적용
- **골드·레벨 보상**
  - 종합 성적표(S, A, C 등)에 따라 골드 지급  
  - *최고 등급(Min-Max) 누적 방식*  
    - 예: 첫 플레이 F → 0골드 / 두 번째 C → 3골드 지급  
    - 이후 A(5골드) 달성 시 기존 C(3) 대비 +2 지급
  - 듀오링고식 “매일 접속·프로그레션 기반 동기부여” 모델 참고

### 2.3. 기술 구조 (AI/서버/클라 협업)
- **단어 설명 기능(LLM 기반)**
  - 클릭 시 “단어 뜻/발음/예시” 제공  
  - 백엔드 DB 저장 방식은 비효율 → **LLM API 호출 + 캐싱 구조** 제안  
  - 동일 질문 반복 시 캐싱된 설명 반환하여 비용 절감
- **개별 튜터 / 전체 가이드 튜터**
  - **개별 튜터:** 유저가 단어·개념을 직접 묻는 Ask 기능  
  - **전체 튜터:** 플레이 흐름 안내(NPC 역할, 길찾기 가이드 등)
  - 전체 튜터는 호스트 기준으로 서버에 요청 → 클라에게 방송
- **협동 플레이 구조**
  - 협동 흐름은 “클라-클라 직통 소통” 가능  
  - 서버 참여 포인트:
    - 퀘스트 시작/종료 이벤트 전달(호스트가 서버에 통합 전달)
    - 단어·설명 등 의미 기반 데이터 반환(LLM API)
- **플로우 차트 기반 시나리오**
  - 주황색: 게임 플레이 단계(유저 체험)  
  - 파란색: 위젯/팝업(UI)  
  - 핑크색: 서버 처리 영역  
  - 현재 드로우아이오 기준 전체 플로우 완성됨 (가급적 변경 없음)

### 2.4. 만장일치로 정리된 요구사항
- 질문지는 **“서비스 설계의 정체성”** → 꼭 필요
- 광고는 **프로토 이후 확장 기능**, 하지만 설계엔 포함
- 상점/면세점 기능은 **향후 버전**에서 언리얼 포트폴리오 강화를 위해 포함 가능
- LLM 캐싱 및 API 구성을 통한 효율적 백엔드 설계 필요
- 시나리오 구조는 확정 수준 → 변경 최소화
