251119 Daily

2025-11-19 데일리 회의

1. 개요

  • 일자: 2025-11-19
  • 참석: 배주백, 이치훈, 이은희, 박종욱, 전민우, 이재진
  • 키워드: 네트워크, 데이터 정의서, 환경 구성, STT, 시나리오, 협동 요소, RDB/레그 설계

2. 논의 요약

2.1. 주요 논의

  • 네트워크 플로우 완성 및 리뷰 필요
    • 서버·클라이언트 데이터 공유 정의 완료
    • 사운드 데이터는 PCM/raw가 아닌 메타포맷(WAV/OGG)으로 전송 필요
    • Swagger 기반 API 검증 후 UE5 로직 삽입 예정
  • 협동 플레이의 기획적 정당성 확보 필요
    • 강사의 피드백: “왜 협동인가?” → 네트워크 자체로 해결할 수 없는 학습적 협력 설계 필요
    • 아이디어: 선착자 → 후발 플레이어에게 RPC 기반 힌트(마킹·트레일) 제공
  • 시나리오 구조 결정 논의
    • 시나리오 난이도 상승은 오브젝트 증가보다 ‘질문 변환(LLM)’이 현실적
    • 단어 기반 → 문장 기반으로 증가시키는 방향 논의
    • RDB로 테이블 구성 vs 레그 자체를 시나리오 저장소로 활용 여부 검토

2.2. 기술 / 기획 관련 논의

  • 3D 환경 작업 우선순위 확정
    • 플레이어 캐릭터가 완성되었으므로 “환경”을 선행해야 전체 기능 테스트 가능
    • 자동문·광고판·기본 공간 배치 우선
  • 치훈: 1인칭 전환 → 그림판/컨베이어 기능 예정
  • 은희: 환경 구축 및 리소스 선택(무료 에셋 포함)
  • 주백: 네트워크·사운드·HTTP/Socket 통신 구조 담당
  • 백엔드: 계정→토큰→플레이 인포 흐름 구현 준비됨

2.3. 일정 / 운영 관련 논의

  • 네트워크 세션은 이번 주 필수 아님, 11/30~12/2 사이 테스트 목표
  • 12월 9일 PBT 발표 대비:
    • 이번 주: 환경·기본 Flow
    • 다음 주: 세션·STT/TTS·시나리오 연동
  • 지라 일정이 일부 비어 있어 이번 미팅 후 재할당 필요

3. Action Items

클라이언트 팀

  • [ ] 환경 구성(자동문, 공간 배치, 광고판) — 담당: 이은희 / 기한: 11-21
  • [ ] 1인칭 캐릭터 수정 및 그림판/컨베이어 프로토타입 — 담당: 이치훈 / 기한: 11-22
  • [ ] 네트워크 기반 HTTP/소켓 구조 삽입 — 담당: 배주백 / 기한: 11-24

AI 팀

  • [ ] 시나리오 난이도/LLM 변환 룰 설계 — 담당: 박종욱 / 기한: 11-25
  • [ ] STT 모델 테스트 및 LLM 응답 구조 정리 — 담당: 이재진 / 기한: 11-22

DevOps / 전반

  • [ ] 지라 이슈 보강(환경/시나리오/네트워크 항목 재배치) — 담당: 전민우 / 기한: 11-20
  • [ ] 데이터 정의서 → RDB/레그 선택안 정리 — 담당: AI/클라 공동 / 기한: 11-21

4. 회고

4.1. 잘된 점 (Keep)

  • 네트워크 플로우 문서화가 완료되어 팀 전체의 이해도 상승
  • 사운드 포맷 등 기술적 제약 요소가 조기에 식별됨
  • 기획·시나리오·AI·클라이언트 간 데이터 구조 논의가 단일 흐름으로 정리됨
  • 팀 내 상호 리뷰가 자연스럽게 진행됨

4.2. 미진한 점 (Problem)

  • 협동 플레이의 “교육적 목적”이 아직 충분히 설득력 있게 잡히지 않음
  • 환경 구성 우선순위가 늦게 합의되어 전체 개발 흐름 지연 우려
  • 지라 이슈 재정렬이 필요해 일정 가시성이 떨어짐
  • 시나리오 저장 구조(RDB/레그) 결정이 지연됨

4.3. 다음 단계 (Try)

  • 시나리오 난이도 변화는 오브젝트 추가가 아니라 LLM 기반 문장 변환 중심으로 설계하기
  • 협동 요소는 “먼저 푼 사람이 도와준다”는 방향으로 명확성 확보
  • 환경을 선행하여 전체 흐름 테스트 루프(로그인→환경→문제풀이)가 가능하도록 맞추기
  • 데이터 정의서 기반으로 AI/클라이언트/서버의 단일 구조 확정
  • 지라 일정 자동화/정렬을 통해 업무 속도 개선
