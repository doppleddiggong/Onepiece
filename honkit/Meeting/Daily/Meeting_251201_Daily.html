251201 Daily

2025-12-01 데일리 회의

1. 개요

  • 일자: 2025-12-01
  • 참석: 배주백 외 팀원
  • 키워드: 인터뷰 API, Step2~4 테스트, Redis 캐싱, STT/TTS, 발표 시연 준비

2. 논의 요약

2.1. 주요 논의

  • 인터뷰 API 구조 정리 및 연동 준비

    • hello / post single / post batch API 사용 범위 명확화
    • 클라이언트는 토큰 자동 헤더 삽입 방식으로 개발
    • Swagger에서 토큰 삽입은 제한적 → Postman 사용 권장

  • 쓰기·듣기·말하기 테스트 기본 구조 확정

    • 쓰기: 글자 수 제한보다 스크롤 UI 기반 입력
    • 듣기: 서버 음성 데이터를 바이너리 → Wave 파일 변환 → 재생
    • 말하기: 초기 버전은 단문 평가 기반
      • 평가 기준은 50~70점 사이
      • STT → 텍스트 평가 우선 적용
      • TTS 피드백은 알파 이후 확장

  • 시나리오 구조 통일 필요

    • 기존 1,2,3,4 숫자 기반 → READ / WRITE / LISTEN / SPEAK Enum으로 전환
    • GameState/GameMode에 시나리오 시스템 구성
    • NPC 심사관도 시나리오 시스템 사용

  • 서버 사이드 Redis 캐싱

    • 생성된 인터뷰/문제 데이터를 유저별로 Redis에 저장
    • 평가 요청 시 시나리오 ID 기반으로 정답 매칭 처리

  • Postman 교육 필요

    • 팀 내 API 테스트 경험 부족
    • Postman으로 토큰/헤더/폼데이터 테스트 방법 공유 예정

  • 프로토타입 발표 방향 조정

    • 문서 중심 발표 → 시연 위주로 변경
    • Step1~4 전체 학습 흐름이 돌아가는 형태가 핵심
    • 슬라이드는 구성도 1장 + 시나리오 차트 1장 정도로 최소화

3. Action Items

클라이언트 팀

  • [ ] 인터뷰 UI ↔ API 연동 (담당: 배주백)
  • [ ] 쓰기 UI 스크롤 입력 구조 구축 (담당: 치훈)
  • [ ] 듣기 테스트: 오디오 바이너리 파싱 및 재생 처리 (담당: 은희)
  • [ ] 말하기 테스트: STT → 평가 요청 구조 1차 구현 (담당: 민우)
  • [ ] 시나리오 Enum(READ/WRITE/LISTEN/SPEAK) 통합 및 GameState 반영 (담당: 배주백)
  • [ ] RPC/컨베이어 등 기존 버그 정리

AI / 서버 팀

  • [ ] 인터뷰 생성 API 안정화 및 Redis 캐싱 반영 (담당: 종욱)
  • [ ] 말하기 평가 에이전트 추가 조정 (점수 기준·오류 처리)
  • [ ] Postman 테스트 시나리오 예제 작성

DevOps / 전반

  • [ ] 발표용 시스템 구성도 제작(클라/서버/AI 흐름 요약)
  • [ ] 금요일까지 기능 프리징 + 주말 전 발표 준비

4. 회고

4.1. 잘된 점 (Keep)

  • Step2~4 착수에 필요한 API/시나리오 기반이 모두 확보됨
  • 인터뷰·쓰기·듣기·말하기의 전체 플로우가 연결되기 시작함
  • Redis 활용한 서버 캐싱 구조가 확립됨
  • 발표 방식이 시연 중심으로 정리되어 개발 집중도 상승

4.2. 미진한 점 (Problem)

  • 시나리오 Enum 불통일로 로직 분기 혼잡
  • Postman / API 테스트 역량 부족
  • 말하기 테스트의 연속 대화(멀티턴)는 아직 미구현
  • 발표까지의 완성도 확보 일정이 촉박함

4.3. 다음 단계 (Try)

  • Step1~4의 실제 학습 루프 완성
  • 말하기 테스트의 STT/TTS 흐름 고도화
  • 전체 API 문서화 및 Postman 테스트 정리
  • 발표 자료 최소화 + 시연 품질 극대화
